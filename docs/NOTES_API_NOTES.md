# Apple Notes AppleScript automation — ground-truth recon notes

> ## ⚠️ Correction (T13): the `body` getter is lossy — do not use it as an oracle
>
> Everything in section 3 below was derived by writing HTML into a note and
> reading `body of note` back. **That read-back is itself lossy**, so several
> conclusions drawn from it are wrong. Verified live on macOS 26.6.2 by
> importing a note through Notes' Evernote importer and comparing what the
> screen shows against what the getter returns:
>
> | Actually in the note | What `body of note` returns |
> |---|---|
> | a live, clickable hyperlink | `<u>label</u>` — the `href` is gone |
> | a native checklist item | a plain `<li>` — the checkbox is gone |
> | a real numbered list | `<li>`s inside the preceding `<ul>` |
>
> Consequences for the notes below:
>
> * **"Notes flattens nested `<ol>`" (section 3) is false.** A properly nested
>   `<ol>` inside a `<ul>` renders as a real numbered sub-list. That claim came
>   from a probe that sent a *sibling* `<ol>` and from reading the lossy getter.
> * **"Notes strips `<a href>` on input" is true** for the AppleScript `body`
>   writer specifically — confirmed against 7 anchor shapes, including inline,
>   inside `<p>`, inside `<li>`, `mailto:`, with extra attributes, and via
>   `set body` after creation. It is *not* true of Notes generally: the
>   Evernote importer produces working links.
> * The getter *does* faithfully report **list nesting depth**, which is what
>   `notes_indent.py` uses to verify the checklist indentation pass.
>
> Any future capability claim must be checked visually (screenshot or manual
> inspection), never by a `body` read-back alone.

### Checklist indentation is not expressible in ENML

All thirteen shapes below produce **top-level** checklist items:

`<en-todo>` inside `<li>`; sibling-`<ul>` style; `padding-left`; `margin-left`
(Evernote's own convention); physically nested `<div>`s with margins;
`<blockquote>` and nested `<blockquote>`; `margin-left` on the `<ul>`; bare
nested `<ul>` with no `<li>`; `text-indent`; `<en-todo>` inside `<ol>`; a bullet
parent with `<en-todo>` children. `margin-left` on the `<li>` *does* indent —
but loses the checkbox. Leading non-breaking spaces indent cosmetically while
keeping the checkbox.

The Notes **editor** indents a checklist item natively when Tab is pressed on
it, keeping the checked state, and that change *is* visible through the `body`
getter as nested `<ul>`s — which is what `notes_indent.py` exploits and how it
verifies itself.

### Import mechanics

* One confirmation sheet per file, regardless of note count.
* Each import creates a fresh, numbered landing folder (`Imported Notes`,
  `Imported Notes 1`, …); it never merges into an existing one.
* `move note id … to folder id …` works (it is absent from the scripting
  dictionary but functional) and preserves links and checkbox state.
* `set container of note` does **not** work.
* The scripting dictionary offers no checklist type and no import command:
  the whole suite is `account`, `folder`, `note`, `attachment`, plus `show`
  and `open note location`.
